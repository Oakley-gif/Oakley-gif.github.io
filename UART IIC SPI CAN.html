一、四种协议快速对比表

校招面试中，常会直接问“对比一下 UART、I2C、SPI 和 CAN”，建议先记住下面这张对比表，再展开细节：

  • 波特率：单位时间内传输的符号（码元）个数，单位 Baud。

  • 比特率：单位时间内传输的比特（二进制位）个数，单位 bps（比特每秒）。

  • 比特率 = 波特率 × 每个符号携带的比特数

    其中“每个符号携带的比特数”取决于调制方式（或编码方式）。 如果用二进制调制（一个符号只有0和1两种状态），则一个符号=1比特，此时波特率 = 比特率。 如果使用更高阶调制（如QPSK、8QAM等），一个符号可以代表多个比特，此时比特率 > 波特率。

二、UART（通用异步收发器）

Universal Asynchronous Receiver/Transmitter

1. 协议内容

UART 是一种异步、全双工、点对点的串行通信协议。由于没有共享时钟线，收发双方必须预先约定相同的波特率和帧格式才能正确通信。

物理连接：只需两根信号线——TXD（发送）和 RXD（接收），通信时需交叉连接（本机的 TX 接对方的 RX，反之亦然）。

帧格式：一个完整的 UART 数据帧包含：

  • 起始位：1 位，逻辑 0，标志传输开始

  • 数据位：5~9 位（最常见 8 位），LSB 先发

  • 校验位：可选，奇校验/偶校验，用于错误检测

  • 停止位：1~2 位，逻辑 1，标志传输结束

空闲时总线保持高电平。当检测到起始位（高→低跳变）时，接收方开始按约定波特率采样数据。

核心参数：波特率（Baud Rate），表示每秒传输的二进制位数。常见值有 9600、115200。收发双方波特率误差超过约 3% 会导致通信失败。

电气层变体：UART 只定义了协议层，实际应用中需配合电平标准：

  • TTL/CMOS：逻辑 1≈VCC（3.3V/5V），逻辑 0≈0V，板内短距离通信

  • RS-232：逻辑 1 为 -3V~-15V，逻辑 0 为 +3V~+15V，适用于 PC 串口，需 MAX232 电平转换

  • RS-485：差分信号传输，抗干扰能力强，支持多点通信（最多 32/256 节点），传输距离可达 1200 米

2. 优缺点

优点：

  • 协议简单，硬件实现容易，几乎所有 MCU 都内置 UART 外设

  • 全双工，可同时收发

  • 只需两根线，引脚占用极少

  • 配合 RS-485 可实现长距离多节点通信

缺点：

  • 速度较慢，通常 ≤115200 bps（高速 UART 可达数 Mbps 但较少用）

  • 异步通信，双方波特率必须严格匹配，否则乱码

  • 仅支持点对点（除非配合 RS-485 等总线物理层）MOBUS

  • 无硬件流控时，接收方处理不过来会导致丢包

3. 应用场景

  • PC 与单片机调试通信（通过 USB 转串口）

  • GPS 模块、蓝牙模块、WiFi 模块等外设通信

  • 工业现场总线（配合 RS-485）

  • 嵌入式系统日志输出（printf 重定向到串口）

三、I2C（集成电路总线）

1. 协议内容

I2C（Inter-Integrated Circuit，也称 IIC）是一种同步、半双工、多主多从的串行总线，由飞利浦公司（现 NXP）开发。仅需两根信号线：

  • SDA：串行数据线（双向）

  • SCL：串行时钟线（由主机产生）

两根线均采用开漏输出结构，因此必须外接上拉电阻（典型值 2.2kΩ~10kΩ）才能输出高电平。开漏设计使得总线支持“线与”逻辑，便于实现多主仲裁和时钟拉伸。

线与特性：只要有一个设备将总线拉低（输出低电平），总线就呈现低电平； 只有当所有设备都释放总线（输出高阻态），总线才会被上拉电阻拉成高电平。

关键时序：

  • 起始条件：SCL 为高电平时，SDA 由高→低跳变

  • 停止条件：SCL 为高电平时，SDA 由低→高跳变

  • 数据有效性：SCL 高电平期间 SDA 必须保持稳定；SDA 只能在 SCL 为低电平时改变

  • 应答（ACK/NACK）：每传完 8 位数据，第 9 个时钟周期由接收方拉低 SDA 表示应答

通信格式：

起始位 | 从机地址（7位）+ 读写位（1位）| ACK | 寄存器地址 | ACK | 数据 | ACK/NACK | 停止位

其中读写位：0 = 主机写，1 = 主机读。7 位地址模式下，一条总线最多可挂 127 个设备。

速率标准：标准模式 100kbps、快速模式 400kbps、快速+模式 1Mbps、高速模式 3.4Mbps。

多主仲裁：当多个主机同时启动通信时，通过检测 SDA 电平进行仲裁。仲裁在地址段进行，谁先输出低电平谁赢得总线（地址小的优先级高），且仲裁不破坏数据。

I2C总线上可以挂多个“主机”（比如多个单片机都想发数据）。为了防止它们同时说话造成冲突，I2C用了一个很聪明的办法：谁发“0”谁赢，发“1”的自动退让。

具体来说，I2C的线路设计成“线与”——只要任何一个主机把线路拉低（发0），整条线就是低电平；只有当所有主机都不拉低（都想发1）时，线路才会被电阻拉回高电平。所以当多个主机同时发送数据时，它们会一位一位地比较：如果某个主机想发1（高电平），但检测到线路上实际是0（说明有别的主机在发0），那它就知道自己输了，立刻乖乖退出，不再干扰赢家。而赢家（发0的那个）可以继续发完剩下的数据。

整个过程由硬件自动完成，不会丢失数据，也不需要事先商量，就像一群人都想说话，但规则是“谁先压低声音（0）谁就说，想抬高声音（1）的听到别人更低就闭嘴”——简单又可靠。

2. 优缺点

优点：

  • 仅需两根线，引脚占用极少，硬件实现简单

  • 支持多主多从架构，最多 127 个设备共享同一总线

  • 有完善的仲裁机制和应答机制，通信可靠

  • 支持时钟拉伸，慢速从设备可拉低 SCL 让主机等待

缺点：

  • 速率相对较慢（标准 100kbps，最高 3.4Mbps）

  • 半双工，同一时刻只能单向传输

  • 传输距离短（标准模式下约 1 米）

  • 总线上拉电阻需根据总线电容精心选择

  • 总线被拉死时排查困难（某设备一直拉低 SDA）

3. 应用场景

  • 各类传感器（温度、湿度、加速度、陀螺仪等）

  • EEPROM、FRAM 等非易失性存储器

  • RTC 实时时钟芯片

  • 电源管理芯片（PMIC）配置

  • 触摸屏、显示屏的配置接口

四、SPI（串行外设接口）

1. 协议内容

SPI（Serial Peripheral Interface）是一种同步、全双工、高速的串行通信总线，由 Motorola 推出。采用一主多从架构。

信号线（标准 4 线制）：

  • SCK：串行时钟，由主机产生

  • MOSI：主机输出、从机输入（Master Out Slave In）

  • MISO：主机输入、从机输出（Master In Slave Out）

  • CS/SS：片选信号（Chip Select / Slave Select），低电平有效，主机通过拉低不同从机的 CS 线来选择通信对象

数据交换机制：主机和从机内部都有一个移位寄存器，在 SCK 的每个时钟周期，主机通过 MOSI 发送一位数据，同时通过 MISO 接收一位数据。发送完一个字节后，双方寄存器内容完成交换。

四种工作模式（由 CPOL 和 CPHA 两个参数组合决定）：

主从双方必须使用相同模式，否则数据错位。模式 0 和模式 3 最常用，因为它们都在上升沿采样数据。

SPI 没有标准协议层，数据格式（位宽、MSB/LSB 先行）由具体器件决定，非常灵活。

2. 优缺点

优点：

  • 全双工，可同时收发数据

  • 速率极高（可达几十 MHz，远超 I2C）

  • 协议简单，无需设备地址，无应答机制

  • 推挽输出，无需上拉电阻，信号质量好，功耗低

缺点：

  • 每个从机需要一根独立的 CS 线，多设备时引脚占用多

  • 无标准协议层，不同器件的时序要求可能不同

  • 无应答机制，主机无法确认从机是否正确接收

  • 传输距离短，通常仅适用于板内通信

  • 无仲裁机制，同一时刻只能有一个主机

3. 应用场景

  • Flash 存储器（SPI NOR Flash、SPI NAND Flash）

  • SD 卡（SPI 模式）

  • LCD/OLED 显示屏

  • 高速 ADC/DAC

  • 射频模块、移位寄存器

五、CAN（控制器局域网络）

1. 协议内容

CAN（Controller Area Network）是一种多主、异步、高可靠性的串行总线，由 Bosch 公司为汽车电子系统开发，后成为国际标准（ISO 11898）。与前三者最大的区别在于：CAN 专为工业级可靠性和实时性设计。

物理层：使用差分信号传输，两根信号线为 CAN_H 和 CAN_L。通过两根线的电压差表示逻辑电平：

  • 显性电平（逻辑 0） ：CAN_H - CAN_L ≈ 2V

  • 隐性电平（逻辑 1） ：CAN_H - CAN_L ≈ 0V

显性电平可覆盖隐性电平（“线与”逻辑），这是仲裁机制的物理基础。

在CAN总线通信中，显性电平（逻辑0）之所以能覆盖隐性电平（逻辑1），是因为显性电平是靠收发器“主动用力驱动”总线产生的，而隐性电平只是所有收发器都“松开手”、靠电阻轻轻拉回的状态。这就好比一扇门：只要有人用力推（显性），门就会被推开；只有当所有人都松手（隐性），门才会靠弹簧自己关上。因此，只要总线上有一个节点发送显性位，整个总线就会被强制拉成显性状态，而隐性位只有在所有节点都不输出显性时才能体现出来。

差分传输具有很强的抗共模干扰能力，适合恶劣电磁环境。

总线仲裁：CAN 采用非破坏性逐位仲裁机制。每个节点在发送数据时同时监听总线：

  • 如果监听到的电平与自己发送的一致，继续发送

  • 如果不一致，说明有更高优先级的节点在发送，该节点自动退出发送，转为接收模式

仲裁在帧 ID 段进行，ID 值越小，优先级越高。这种机制不破坏正在传输的数据，保证了高优先级消息的实时性。

帧格式：CAN 2.0 规范定义了以下帧类型：

  • 数据帧：传输实际数据，分为标准帧（11 位 ID）和扩展帧（29 位 ID）

  • 远程帧：请求发送具有相同 ID 的数据

  • 错误帧：检测到错误时发送

  • 过载帧：请求延迟下一次发送

  • 帧间隔：分隔前后两个帧

数据帧包含：帧起始 + 仲裁场（ID + RTR）+ 控制场 + 数据场（0~8 字节）+ CRC 场 + 应答场 + 帧结束。

短帧结构：一个数据帧最多携带 8 字节数据，这使得发送和接收时间短、被干扰的概率小，保证了高实时性和抗干扰能力。

错误处理：CAN 内置完善的错误检测机制（位错误、CRC 错误、格式错误、应答错误、位填充错误），并支持错误计数和自动总线关闭功能。

2. 优缺点

优点：

  • 差分信号 + 短帧结构，抗干扰能力极强

  • 多主架构，任意节点可主动发送

  • 非破坏性仲裁，高优先级消息实时性有保障

  • 完善的错误检测和故障隔离机制

  • 节点可热插拔，扩展性好

  • 传输距离远（低速模式下可达数公里）

缺点：

  • 数据吞吐量有限（经典 CAN 最高 1 Mbps，单帧 ≤8 字节）

  • 协议复杂，需专用 CAN 控制器和收发器

  • 相对 UART/SPI/I2C 成本较高

  • 缺乏内置安全加密功能

CAN FD 升级：CAN FD（Flexible Data-rate）将数据段速率提升至 5~8 Mbps，数据场扩容至 64 字节，向下兼容经典 CAN。

3. 应用场景

  • 汽车电子：发动机控制、变速箱控制、ABS 刹车系统、车身电子、仪表盘、空调系统

  • 工业自动化：PLC 通信、伺服控制、现场总线

  • 医疗设备：手术机器人、监护仪、诊断设备

  • 航空航天：飞行控制系统

六、校招面试高频考点汇总

以下是校招面试中关于这四种协议的最高频问题，建议逐条掌握：

（一）UART 高频考点

Q1：UART 的帧格式是什么？空闲时总线电平状态？

答：起始位（1 位逻辑 0）+ 数据位（5~9 位）+ 校验位（可选）+ 停止位（1~2 位逻辑 1）。空闲时 TX 和 RX 线均保持高电平。接收方检测到下降沿（起始位）后开始按约定波特率采样数据。

Q2：波特率是什么？波特率误差多大会导致通信失败？

答：波特率表示每秒传输的二进制位数（bps）。收发双方波特率误差一般需控制在 < 3%，否则采样点漂移累积会导致数据误判。设计晶振时优先选择能使分频系数为整数的频率（如 115200 bps 用 11.0592 MHz 晶振误差为 0%）。

Q3：TTL、RS-232、RS-485 三者的区别？分别适用什么场景？

答：见下表：

TTL 直接接 RS-232 会烧坏 MCU 引脚，需使用 MAX232 等电平转换芯片。

Q4：UART 丢包/乱码如何排查？

答：软件方面——检查波特率配置是否一致、校验位/停止位设置是否匹配、中断/轮询接收方式是否合理；硬件方面——确认 RX/TX 是否正确交叉连接、是否存在电平不匹配问题、晶振频率是否导致波特率误差超标。

（二）I2C 高频考点

Q5：I2C 为什么必须加上拉电阻？上拉电阻选多大？

答：I2C 的 SDA 和 SCL 为开漏输出，只能输出低电平，无法主动输出高电平。因此必须外接上拉电阻来提供高电平。开漏设计的好处是支持“线与”逻辑，便于多主仲裁和时钟拉伸，同时避免多设备同时输出时短路。上拉电阻典型值 2.2kΩ~10kΩ，具体取决于总线电容负载和通信速率。

Q6：I2C 起始条件和停止条件如何区分？

答：

  • 起始条件：SCL 为高电平时，SDA 由高→低跳变

  • 停止条件：SCL 为高电平时，SDA 由低→高跳变 起始和停止条件均由主机发出。

Q7：I2C 多主仲裁是如何实现的？

答：多个主机同时启动通信时，在发送地址段的同时监听 SDA 线。如果某主机发送隐性电平（高）但监测到 SDA 为低，说明有其他主机在发送显性电平，该主机自动退出发送。仲裁不破坏数据，仲裁失败的节点自动转为从机模式。

Q8：I2C 通信挂死（总线一直被拉低）如何排查？

答：软件方面——检查是否正常发送了停止条件、ACK/NACK 处理是否正确；硬件方面——用示波器/逻辑分析仪查看 SDA/SCL 波形，逐级断开从设备定位哪个设备在拉低总线，检查上拉电阻是否虚焊或阻值过大。

Q9：I2C 一个总线上最多能挂多少个设备？

答：7 位地址模式下最多 127 个（排除保留地址 0x00），但实际数量受限于总线电容负载（总负载电容 ≤400 pF）和上拉电阻驱动能力。

Q10：I2C 地址写和读的格式有何不同？

答：写操作：起始 + 从机地址（7 位）+ 写位（0）+ ACK + 寄存器地址 + ACK + 数据 + ACK + 停止。读操作：起始 + 从机地址 + 写位（0）+ ACK + 寄存器地址 + ACK + 重复起始 + 从机地址 + 读位（1）+ ACK + 读取数据 + NACK + 停止。

（三）SPI 高频考点

Q11：SPI 四种工作模式的区别？分别由什么参数决定？

答：由 CPOL（时钟极性） 和 CPHA（时钟相位） 两个参数组合决定：

主从双方必须使用相同模式，模式 0 和 3 最常用（均在上升沿采样）。

Q12：SPI 如何实现一主多从？

答：主机通过多条独立的 CS（片选）线连接各个从机。需要与哪个从机通信，就拉低对应的 CS 线，其他从机 CS 保持高电平。同一时刻只能有一个从机被选中。

Q13：SPI 的数据交换机制是怎样的？

答：主机和从机内部各有一个移位寄存器，在 SCK 的每个时钟周期，主机通过 MOSI 发送一位数据的同时，通过 MISO 接收一位从机的数据，两个移位寄存器形成闭环。发送一个字节后，双方寄存器内容完成交换。

Q14：软件 SPI 和硬件 SPI 有什么区别？

答：软件 SPI 通过 GPIO 手动模拟时序，任意引脚可用但速率受限（通常几十 kHz~几百 kHz），且易受中断干扰；硬件 SPI 由 MCU 内置 SPI 外设完成，速率高（可达几十 MHz），支持 DMA，时序稳定。面试中应说明两种方式的优缺点并举例适用场景。

Q15：SPI 和 I2C 如何选择？

答：需高速传输、全双工通信时选 SPI（如 Flash、显示屏）；引脚资源紧张、需要连接多个低速设备时选 I2C（如多传感器）。I2C 仅需 2 根线即可连接多个设备，SPI 则需要为每个从机提供独立 CS 线。

（四）CAN 高频考点

Q16：CAN 总线的显性电平和隐性电平分别代表什么逻辑？

答：显性电平（逻辑 0）：CAN_H - CAN_L ≈ 2V；隐性电平（逻辑 1）：CAN_H - CAN_L ≈ 0V。显性电平可覆盖隐性电平（线与逻辑），这是仲裁机制的物理基础。

Q17：CAN 总线如何实现仲裁？为什么说 CAN 的仲裁是非破坏性的？

答：CAN 采用逐位仲裁机制。每个节点发送数据的同时监听总线，若监听到的电平与自己发送的不一致，说明有更高优先级的节点在发送，该节点立即停止发送并转为接收模式。仲裁在帧 ID 段进行，ID 值越小，优先级越高。“非破坏性”指仲裁失败的节点不会破坏正在传输的数据，且高优先级消息无需重传即可直接发送。

Q18：CAN 的数据帧最多能传输多少字节数据？为什么这样设计？

答：经典 CAN 数据帧最多传输 8 字节，CAN FD 可扩展到 64 字节。短帧结构使得发送和接收时间短、被干扰的概率小、实时性高，非常适合汽车和工业控制等对实时性和可靠性要求苛刻的应用场景。

Q19：CAN 有哪些错误检测机制？

答：CAN 内置五种错误检测机制：位错误（发送时监测总线电平与预期是否一致）、CRC 错误、格式错误、应答错误（ACK 位未收到应答）、位填充错误（连续 5 个相同极性位后未插入反型位）。节点通过错误计数器进行故障隔离，错误过多时自动退出总线。

Q20：CAN 总线两端为什么要加终端电阻？阻值是多少？

答：终端电阻用于消除信号反射，保证总线阻抗匹配。CAN 总线标准规定两端各接 120Ω 终端电阻（共模阻抗 60Ω）。高速 CAN（ISO 11898-2）必须加，低速容错 CAN 可内置。不加终端电阻会导致信号反射，波形畸变，通信不稳定。

（五）综合对比类高频考点

Q21：UART、I2C、SPI、CAN 四者的最大区别是什么？如何选择？

答：

  • 点对点、低速调试 → 选 UART

  • 板内多设备、引脚紧张 → 选 I2C

  • 板内高速通信、外设数据量大 → 选 SPI

  • 工业/汽车级高可靠性、长距离多节点 → 选 CAN

Q22：哪些是同步通信，哪些是异步通信？有什么区别？

答：同步通信（I2C、SPI）需要时钟线来同步数据传输，速率更高、时序更精确；异步通信（UART、CAN）无共享时钟，依赖预先约定的速率（UART）或位定时同步（CAN），更适合长距离传输。

Q23：I2C 的时钟拉伸（Clock Stretching）是什么？有什么作用？

答：当从设备来不及处理数据时，可以将 SCL 线拉低，迫使主机等待。主机检测到 SCL 被拉低后会暂停发送时钟，直到从设备释放 SCL 才继续。这使慢速从设备也能与高速主机通信，是 I2C 的重要流控机制。

Q24：SPI 为什么不需要上拉电阻，而 I2C 需要？

答：SPI 信号线为推挽输出，可主动输出高电平，因此无需上拉电阻；I2C 为开漏输出，只能输出低电平，需要外接上拉电阻来提供高电平，同时也方便实现多主仲裁和线与逻辑。推挽输出的 SPI 在高速传输时信号完整性更好。

七、备考建议

  1. 动手实践：用示波器/逻辑分析仪实际抓取 UART、I2C、SPI 的波形，对照时序图理解，面试时能说出“我看到过这个波形”非常加分。

  2. 画时序图：面试官常要求手画 I2C 的起始/停止条件或 SPI 的四种模式时序，建议提前练习。

  3. 结合项目：准备 1~2 个自己项目中实际用过的协议案例，能说清为什么选这个协议、遇到什么问题、如何解决的。面试官更看重你解决问题的能力。

  4. 多看面经：牛客网、CSDN 上大量嵌入式硬件校招面经，建议至少刷 50 道通信协议相关题目，建立“题目→答案”的条件反射。

  5. 拓展知识：有精力的话可以了解一下 CAN FD（CAN 的升级版）、RS-422、I2S（音频接口）、LIN（汽车低速总线）等，作为加分项。
